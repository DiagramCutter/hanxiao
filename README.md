# 智能防渗墙管控平台

Vue 3 + TypeScript + Vite 单页项目，首页直接显示清孔监测。当前展示回浆监测、新浆监测、三孔清孔进度、泥浆储量、累计换浆量，以及原有三维场地。右侧预留泥浆输送视频监控区，底部槽孔栏暂不显示。

## 本地运行

使用 Node.js 22.17+ 和 pnpm，依赖版本以 `pnpm-lock.yaml` 为准。测试命令已显式启用 TypeScript 类型剥离，兼容 Node.js 22.17。

```sh
pnpm install
pnpm dev
```

默认访问 `http://localhost:63434/`。本项目只有一个页面，不再使用 Vue Router。

## 当前数据接入

回浆监测已接入 `GET /scene/mud`：页面进入时立即请求，之后每 20 秒轮询。请求未结束时不重复发送，页面卸载时清除定时器并取消未完成请求。

- `viscosity_mud`、`density_mud`、`cs_mud`、`temp_mud` 分别展示为粘度、密度、含沙量、温度。数值原样显示，单位固定为 `s`、`g/cm³`、`%`、`℃`，不做倍率换算。
- 空值显示 `--`，有效的 `0` 正常显示。请求失败时清空回浆显示并提示自动重试，下次轮询成功后恢复；不回退演示值，不增加采集时间或过期判断。

泥浆储量已接入 `GET /scene/mud-system`，同样进入页面立即请求、每 20 秒轮询，避免重复请求并在卸载时清理。

- 四项分别绑定 `r10` 制浆池、`r11` 膨化池、`r12` 储浆池、`r14` 泥浆箱，原值显示，单位固定为 `m³`。
- 空值显示 `--`，有效的 `0` 正常显示；失败时清空储量显示并自动重试。
- `r13` 回浆池库存、`r15` 槽孔泥浆面及 `serverTimeStamp` 暂不展示，累计换浆量仍为演示值。

当前孔位、孔深和停留时长已接入 `GET /scene/drilling`，同样进入页面立即请求、每 20 秒轮询，请求防重并在卸载时清理。

- `pileName` 的 `S1-1 / S1-2 / S1-3` 分别显示为 `1-p1 / 1-p2 / 1-p3`，并驱动左侧三孔编号高亮；`holeDepthM` 原值显示，单位固定为 `m`。
- `stayDurationSeconds` 转为分钟显示，最多保留两位小数，例如 `360` 秒显示 `6 min`。仅在 `STAYING` 或 `CONFIRMING` 状态下显示有效的非负整数秒数；不按前端时钟累加。
- 停留状态显示为“已确认 / 确认中 / 暂无深度 / 数据过期 / 历史不足”。缺失、异常或不可用时长显示 `--`，不将其当作 `0`；请求失败时清空顶部三项并自动重试。
- `updatedAt`、倾斜及气流字段暂不展示，也不使用 `updatedAt` 自行判断过期；三维模型仍保持原预览状态。

三孔清孔进度已接入 `GET /scene/progress` 的 `data.items`，进入页面立即请求、每 20 秒轮询，请求防重并在卸载时清理。

- 按 `pileName` 匹配 `S1-1 / S1-2 / S1-3` 并固定三孔顺序，展示接口返回的 `displayName`，缺失名称时使用对应的 `1-p1 / 1-p2 / 1-p3`。
- 孔深、终孔深度、百分比分别使用 `currentDepthM / finalDepthM / progressPercent`；不再使用演示值 `200 m` 或前端计算百分比。例如 `165 / 220 m` 对应后端返回的 `75%`。
- `AVAILABLE` 表示数据可用；`NO_DEPTH_DATA`、缺失孔或无效数值显示 `--`，有效的 `0%` 正常显示。缺失数据时进度条不填充，也不把空值标成 `0%`。
- 当前孔高亮与第三个接口按原始 `pileName` 联动。请求失败时清空三孔数值并自动重试；`updatedAt` 暂不展示。

其余指标仍使用 [cleaningDashboardData.ts](src/views/SceneForklift/cleaningDashboardData.ts) 中的固定数据，顶部标有“部分演示数据”，后续逐个接入接口。

- 新浆四项指标暂为固定演示值。
- 累计换浆量暂为固定演示值。
- 三维模型、相机、材质和机位算法保持原样，展示状态沿用原模型孔位 `S1-1`，暂未跟随真实孔位切换。
- 泥浆输送视频监控区用于展示海康威视监控画面，目前只显示待接入占位，不发起视频请求。后端提供视频流接口后再接入播放器。

## 后续接口接入

接口封装保留在 `src/api/scene.ts`，当前页面调用回浆、泥浆储量、当前孔位与深度、三孔清孔进度四个接口。接入其余接口时可用实际响应替换集中演示数据，注意核对字段、单位和孔位对应关系。

视频监控接入前需确认后端返回的播放地址、流格式、鉴权方式及地址有效期，再确定播放器与续期逻辑；当前不预设海康 SDK 或播放协议。

原有请求前缀为 `/api/scene/*`。开发时由 Vite 移除 `/api` 前缀后，转发到 `VITE_ADMIN_PROXY_PATH` 指定的后端。

现有开发地址在 `.env.development`，默认为 `http://127.0.0.1:13012`；切换环境时可在 `.env.development.local` 中覆盖，格式参考 `.env.example`。`VITE_OPEN` 控制启动时是否自动打开浏览器。

查看已接入的真实数据时，后端服务需单独运行。

## 验证与打包

```sh
pnpm type-check
pnpm lint
pnpm test
pnpm build
pnpm preview
```

部署 `dist/` 到站点根目录。生产服务器需要将 `/api/` 转发到后端，并移除此前缀；Vite 的开发代理不会包含在构建产物中，`pnpm preview` 也只预览静态文件，需另行配置接口代理才能读取真实数据。模型和 Draco 解码器使用站点根路径，当前配置不支持直接部署到子目录。

## 保留的资源

- `public/models/hcangdi2-compressed.glb`：当前场地。

模型维护说明见 [场景二模型](src/views/SceneForklift/siteModel.md)，孔位标定见 [场景二机器定位](doc/场景二机器定位.md)。`scripts/prepare-site-model.mjs` 保留用于更新当前模型；不要直接覆盖原始模型文件。
